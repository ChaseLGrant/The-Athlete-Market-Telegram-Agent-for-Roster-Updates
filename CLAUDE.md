# CLAUDE.md: context for Claude Code

## What this is
The Athlete Market (TAM) Roster Intelligence. It reads **official college rosters and stats**, finds
positions where a program may lose most of its playing time, and posts **one roster opportunity per
sport per day** to Telegram. It also generates an X teaser for manual posting. The owner is Chase
Grant, a beginner coder, so explain changes in plain language and give exact steps whenever
Chase has to do something.

Repo: https://github.com/ChaseLGrant/The-Athlete-Market-Telegram-Agent-for-Roster-Updates (code was built in a
Cowork session that couldn't push; it now lives here and Claude Code sessions work on it directly).

## Non-negotiable product rules
- Never claim a school "needs" a player, has scholarships, or is recruiting, unless an admin entered a
  🟢 VERIFIED NEED with a Tier A/B source URL and the exact quote. Inferred items are 🔵 ROSTER OPPORTUNITY
  and must include: "Roster analysis only. This is not a confirmed recruiting opening from the coaching staff."
  `app/content/guardrails.py` enforces this. Don't weaken it.
- Never fabricate data. Unknown means `None`/NULL, never a guess. Prefer skipping to publishing something doubtful.
- Deterministic code does all the math. The LLM (optional, `LLM_ENABLED`, default model `claude-opus-5` via
  `ANTHROPIC_MODEL`) only classifies odd position strings, constrained to a closed label set (`app/content/llm.py`).
- Crawling must obey robots.txt and Crawl-delay (checked again on every redirect hop), and must never bypass
  CAPTCHAs, logins or bot protection (`app/collectors/http.py`).
- Only admin-approved items publish (dashboard or the private Telegram review chat; same rules in
  `app/pipeline/workflow.py`). At most one post per sport per day, including the dashboard's PUBLISH NOW
  button; a post whose delivery is unknown still uses the day's slot. Nothing is ever re-sent
  (`app/publishing/service.py`).
- A sport posts live only if `live_verified=True` in `app/sports/registry.py`. Flip it only after
  `python -m app.cli verify --sport X` PASSes on real schools AND those saved real pages are added as test
  fixtures. Never flip it on synthetic data alone.
- Secrets live only in env vars / GitHub secrets. Never commit `.env`.

## Layout
- `app/collectors/`: `SourceAdapter` interface, `PoliteFetcher`, Sidearm adapter, fixture adapter (TEST_MODE)
- `app/sports/`: `registry.py` (all 7 sports, `live_verified` flags), `seasons.py` (spring/fall/winter labels),
  `baseball/` (baseball + softball: positions, stats, team_input, analyzer, config, `module.py` hooks),
  `generic/` (shared usage engine: minutes/starts/yards/tackles), `basketball.py`, `soccer.py`, `football.py`
- `app/analysis/common.py`: signal, data quality, confidence, fingerprints, name matching
- `app/pipeline/`: research (`fetch_team_pages` → store → analyze → upsert), opportunities (dedupe, material
  change), revalidate, workflow (approve/reject/edit/schedule/expire), verify (live page check, `--save-pages`)
- `app/publishing/`: telegram client, queue ranking (quality/freshness/variety), service (modes, idempotency,
  live-verified lock), admin_bot + webhook (private review chat with Approve/Reject buttons)
- `app/admin/`: FastAPI + Jinja dashboard (HTTP Basic + CSRF)
- `docs/`: ARCHITECTURE, BASEBALL_METHODOLOGY, SPORTS_METHODOLOGY, SETUP, GITHUB
- `config/programs/<sport>.csv`: programs per sport (non-baseball rows are `active=false` until verified)
- Tests for non-baseball sports use SYNTHETIC Sidearm-style pages (`tests/sidearm_html.py`, fictional
  "Example State"). Real-page fixtures replace/extend them once captured.
- `db/schema.sql`: generated by `python scripts/gen_schema.py`. Regenerate after any model change.

## Commands
```bash
pip install -r requirements.txt
python -m pytest                                   # 141 tests; must stay green
TEST_DATABASE_URL=postgresql://... python -m pytest  # also run against Postgres
python -m app.cli init-db | research --sport all | list | publish-daily --sport all | check-telegram | expire
python -m app.cli verify --sport softball --save-pages captured/   # live page check (writes nothing)
python -m app.cli telegram-whoami | telegram-poll | telegram-webhook --set|--delete
uvicorn app.main:app                                # dashboard at :8000
python scripts/build_csusm_fixture.py              # rebuild test fixtures
# .claude/settings.json installs requirements at the start of each Claude Code session
```

## Modes
- `TEST_MODE=true`: saved fixtures, nothing is sent, items are marked published (mode=test)
- `DRY_RUN=true`: real crawling, nothing is sent, nothing is marked published
- both false: live
